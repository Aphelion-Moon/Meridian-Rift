/tg/ Station 13 - Modules - Types — Var Details - Proc Details

graffiti
/datum/sprite_editor_workspace/custom_sprite/graffiti

A graffiti piece being painted: one view of up to GRAFFITI_MAX_LAYERS layers, in colours that may be translucent.

The layers are alike. Each has its own name, glow and id ("l1", "l2", ...), the bottom one included, so none of the hair's rules for its base layer apply. Layer changes are custom sprite history steps, so undo covers them. The piece keeps no palette: it takes its colours from its paint when it saves, at most GRAFFITI_MAX_COLORS of them. Every change counts the pixels of each colour, so checking a stroke's colour never reads the canvas.

Vars

color_countsPixel value -> how many pixels of all the layers hold it, for each value the paint uses; transparent pixels aren't counted. In the order the layers first use them when counted afresh, then as new values come.
draw_mask_bitsThe draw mask as a compact stroke mask's slots, a bit for each pixel that takes paint, as a poster's canvas has it, or null. A stroke is cut down to it as its points are read (stroke_mask_slots()), so none needs checking.
layer_record_cacheLayer id -> its layer_records() record, kept until the layer's pixels or glow change, so a surface session's composite reads only the layers painted since the last one. Studio sessions never composite, so never fill it.
next_layer_idThe number the next layer's id takes. Ids are never reused in a draft, so the window's choice of layer survives undo.

↑
prepare_selection_placement
(/list/transaction)

Also writes the colours a placement lands as their canonical pixels, and refuses a placement that would take the paint past GRAFFITI_MAX_COLORS colours, and, in a surface session, one that adds paint. A stroke brings one colour, but a placement can bring several, so each one it lands counts, whatever it paints over.

A surface is painted by hand, so its pieces show the staged reveal's work rather than prepared art. A placement there may move, turn, mirror or cut the session's own paint, which never lands more of a colour than it lifts or covers; a paste does, and is refused with a notice.

Arguments:

  • transaction: The placement.

Returns:

  • TRUE/FALSE: Whether anything changes, within the colour limit and, on a surface, without adding paint.

proc
serialize_piece
(name, description)

Returns the piece as the library saves it: every layer, painted or not, each grid indexing a palette of the colours the paint uses, in the order the layers first use them: layer 1 row by row from the top, then each layer above it. A two-tile canvas with nothing painted on its right tile saves one tile wide, though the canvas keeps its width.

Arguments:

  • name: The piece's name.
  • description: Its description.

Returns:

  • list: The canonical piece, as graffiti_validate_piece() would return it.
  • null: Nothing is painted, or the paint uses more than GRAFFITI_MAX_COLORS colours.

Arguments:

  • index: The layer.
  • glow: Whether its paint glows.

Returns:

  • TRUE/FALSE: FALSE when index names no layer or the glow wouldn't change.

proc
set_width
(canvas_width)

Makes the canvas one or two tiles wide where it stands: columns come and go on the right, so paint keeps its place and every layer keeps its id. Paint in columns that go is lost, which has_paint_right_half() lets the caller ask about first. History can't span two widths, so it starts over.

Arguments:

  • canvas_width: GRAFFITI_WIDTH or GRAFFITI_WIDE_WIDTH.

Returns:

  • TRUE/FALSE: FALSE for any other width, or for the width the canvas already has.
