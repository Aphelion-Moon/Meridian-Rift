↑
save
()

Saves as the parent does, then writes the revision it verified over the backup too, so that once a save is written no file keeps what it dropped. The parent makes the backup hold the last revision before it writes the primary, so an interrupted write still recovers that one. A backup that can't be written then leaves the save standing, as the primary holds it, and the next save writes the backup again.

Trust rule: the primary holds the last verified revision, or the backup does after a failed write or a load from the backup; a revision in neither file means the file changed outside the server.

Only the md5 of the last verified revision stays in memory between saves, so its text is read back first for the parent's backup step: from the primary, or from the backup after a failed write or a load from the backup. A save that succeeds, as a load from the primary does, leaves the primary holding the revision. So when it no longer does, unless the last write failed or the file was loaded from its backup, or when neither file does, the file changed outside the server: what the primary holds now, or the backup when there is no primary, becomes the backup instead and stays it until the next save, and the save goes ahead.

Returns:

  • TRUE/FALSE: Whether the file on disk now holds the tree. Its backup does too unless the file changed outside the server or the backup couldn't be written.
