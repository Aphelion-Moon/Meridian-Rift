bug_report_picture
/datum/bug_report_picture

One picture on a report - the in-game capture, a capture of one of the reporter's windows, or their own file.

Its id stays the same through retakes, so the window keeps its card, while take counts the images. The service holds the image itself, we only keep what the window shows about it.

Vars

attachment_idThe service's id for the image it holds
check_untilWhen we stop polling for the service's check of the image
idThe window's id for this picture, the same through retakes
image_stateThe service's state for the image it holds - processing, ready or failed
pendingWhat's happening to a new image the service doesn't have yet - rendering, waiting or uploading
preview_seenWhether the window showed the reporter this image, needed to switch a private picture back to public
public_consentWhether the reporter lets the image go public with the issue
reasonWhy the picture failed, for the window's words - nothing, render, invalid or unconfirmed
sourceWhere it comes from - view, window or file
takeWhich image this is, counting retakes, so the window never shows the last one's preview
taken_atWhen the current image was taken, in REALTIMEOFDAY
titleThe captured window's title, for a window capture

Procs
