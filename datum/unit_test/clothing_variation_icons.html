clothing_variation_icons
/datum/unit_test/clothing_variation_icons

Checks that supports_variations_flags is being used correctly for clothing items that set it.

Also covers the BODYSHAPE_CUSTOM species (Vox, Vox Primalis, Teshari, Monkey), which aren't gated by any flag - they read worn_icon_vox and friends through generate_custom_worn_icon(), so what gets checked there is the icon files, the greyscale_config_worn_* configs that bake into them, and templates that exist but go unreferenced.

proc
check_gags_config
(/obj/item/item_path, /list/context, config_var, config_value)

A species GAGS config only renders when there are colours to render it with, and it has to hold the states the item draws. Returns the config datum when it is set and actually live, so callers can compare what it generates from.

The missing-colours and missing-sprite cases are notices for now because there is a backlog of both - promote them to TEST_FAIL once it is cleared. A config path that does not resolve at all is always a typo, so that one stays a failure.

Arguments:

  • item_path: The item typepath being checked.
  • context: The item_context() list for this item.
  • config_var: Name of the var being checked, for the message.
  • config_value: The config typepath the item has assigned.

proc
species_variants
()

The constant half of the species table - one row per BODYSHAPE_CUSTOM species that generate_custom_worn_icon() serves.

None of this varies per item, so it is built once. initial() has no by-name form, so the per-item values can't live here: the caller pairs each row with its own spelled-out initial() reads, and the key names the var those reads come from. "suffixes" are the greyscale_config subtype names this repo uses for the species - both spellings are in play, see greyscale_configs.dm. "species" is the prototype whose custom_worn_icons sheet generate_custom_worn_icon() falls back to, or null if it has none.
