proc
add_emissives
(/list/output, /list/mutable_appearance/overlays, /obj/item/bodypart/limb, layer_index)

Adds glow or blockers to the emissive plane in the same order as the visible color layers.

Arguments:

  • output - The list of overlays to their flags, which the emissive overlays are added to.
  • overlays - The list of mutable appearances previously generated and colored.
  • limb - The limb containing this bodypart_overlay. Cannot be null, otherwise there's going to be issues with how the emissives are generated, so it won't add them if the limb is missing, somehow.
  • layer_index - The icon state postfix of the layer being drawn. Every sprite on a layer listed in the sprite accessory's emissive_layers glows, regardless of prefs.

proc
build_icon_state_nova
(gender, layer_index, color_layer, feature_key_suffix)

Helper to generate the icon_state for the bodypart_overlay we're trying to draw.

Arguments:

  • gender - The gender of the limb. Can be "f" or "m".
  • layer_index - The icon state postfix of the layer being drawn (e.g. EXTERNAL_FRONT = "FRONT").
  • color_layer - The color_layer of this icon_state, if any. Should be either "primary", "secondary", "tertiary" or null. Defaults to null.
  • feature_key_suffix - A string that will be directly appended to the result of get_feature_key_for_overlay(). Defaults to null.

proc
dirt_shape_overlay
(/list/images, /obj/item/bodypart/limb, layer_index)

Adds a part's dirt to its images at one layer. One container just over them, at their layer and offsets, holds its baked image, kept to the pixels that layer shows (dirt_container_over()). So it joins the layer's own holder and adds no overlay to the mob. Its emissive blocker comes after it (dirt_emissive_blocker()), after the part's own glows and blockers at that layer. A wagging tail's container holds its wag's dirt. It plays in step with the tail's wagging images, because the same redraw draws them (/datum/component/dirtiness/proc/ready_wag_masks()). Every mutant part's get_overlay() calls it, so a part that takes no dirt (dirt_shape_kinds()) leaves at the first check.

Arguments:

  • images: The part's images at the layer, as get_overlay() returns them, added to.
  • limb: The limb it's drawn on.
  • layer_index: The layer's EXTERNAL_* key.

proc
dirt_shape_render_key
(/list/key, /obj/item/bodypart/limb)

Adds the key of a part's dirt's masks after DIRT_PRIVATE_KEY, or "pending" while they're made, so its limb's images follow the masks. For a wagging tail, they're its wag's masks (ready_wag_masks()). So the tail is drawn again as a wag starts and stops, and once its frames are made. Asking queues masks not made yet. A still tail asks for no frames. It drops the job of the frames its dirt changed under, unless its next wag would ask for the same. A still part is read through its own render key (dirt_shape_source_of()). Every mutant part's icon_render_key() calls it.

Arguments:

  • key: The part's render key, as icon_render_key() returns it, added to.
  • limb: The limb it's drawn on.

proc
dirt_shape_source_of
(/obj/item/bodypart/limb, wagged, /list/own_key) as /datum/dirt_shape_source

Returns the part as dirt reads it: each of its layers' images, as get_images() draws them (dirt_read_shape()). Returns null when it takes no dirt, draws nothing, or sits on no canvas. It's read again when what get_images() reads changes. A tail is read still, and separately wagging, as dirt_wag_frames() makes of it. Each read is kept until the next. A still read given the part's own render key is found again through it (dirt_shape_own_read). That works because the key holds the feature key, base state and sheet that the read's key is built from.

Arguments:

  • limb: The limb it's drawn on.
  • wagged: Whether to read a tail wagging.
  • own_key: For a still read of a part that isn't wagging, its own render key without its dirt, as icon_render_key() builds it, or null.

proc
get_sprite_overlay_flags
(/mob/living/carbon/human/owner)

Returns the overlay flags for this overlay's sprites.

Bodypart textures are filters centered on each sprite, one tile wide. Sprites bigger than a tile, like wings, taurs and big ears, get the wide or tall flag so the texture covers all of them. Sizes come from the icon file itself, not the sprite accessory's dimensions, which only matter when centering.

Arguments:

  • owner: The mob the sprites are drawn for, since some accessories pick their icon per mob. Can be null.
