# Recolourable Bulky Augments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship recolourable, emissive-lit augment finishes on the Muscular outline, with per-slot colours saved in character
setup and an in-room colour editor in the Augments+ stage.

**Architecture:** Each finish is a `/datum/robotic_style/recolorable` subtype drawing three generated sheets: a skin base
(the limb's own greyscale image, tinted by skin), and two channel-packed states (`_paint`, `_glow`) drawn as copies of the limb
image with numeric 4x4 colour matrices; lights are a `_e` mask through tg's `is_emissive`. Colours live in
`/datum/preferences/var/augment_limb_colors`, reach the tgui through a new middleware (constant data once, partial updates),
and the editor recolours a spritesheet preview on the GPU with SVG `feColorMatrix` filters.

**Tech Stack:** DM (BYOND 516, tgstation + Nova + Aphelion), tgui (React, TypeScript, SCSS, bun), Python 3 + PIL (generator).

**Spec:** `docs/superpowers/specs/2026-10-14-recolorable-augments-design.md`. Read it first; this plan argues from it.

## Global Constraints

- **Pol's rules:** never commit, push, stash, reset or open a PR; leave everything in the working tree; preserve unrelated
  changes. No `// APHELION EDIT` markers in `modular_aphelion/` or `modular_nova/` (both are Aphelion-owned); tg files
  (`code/`, `tgui/` outside Aphelion files) get them. Prefer modular code.
- **Builds:** no compile after every edit. Static checks while iterating; compile and run tests at the milestones named in
  Task 9. Never start `dd.exe`/`dreamdaemon.exe` or compile while `tasklist` shows `dreamdaemon.exe` (Pol's live server);
  check `df -h /c` first (C: has ~16 GB).
- **Comments:** terse inline comments; every proc gets a full `/** */` doc block (see `modular_aphelion/modules/fitness/code/fitness_limbs.dm`).
- **DM idioms:** `for(var/key, value in list)` for key/value loops; typed locals before proc calls on loop values;
  `TEST_ASSERT*` in `code/modules/unit_tests/~nova` tests; no `sleep(0)`.
- **Colour strings:** a finish's colours are `"#rrggbb"` four times run together, lowercase, channel order paint, accent,
  frame, lights (28 characters), validated by `^(#[0-9a-f]{6}){4}$`.
- **Matrices:** numeric 16-entry lists only, never rows of colour strings (spec 3.6).
- **Sheets:** `modular_aphelion/modules/bulky_augments/icons/{bulky_augments,bulky_augments_humanoid,bulky_augments_paint}.dmi`
  are generated by `python tools/bulky_augments/gen_augment_sheets.py`; never hand-edit them.
- **Finish ids today:** `jet`, `silverhand`, `ghostrunner`, `maelstrom_wired`, `gorilla`, `maelstrom_brute`. Four more
  (`synthflesh`, `maine`, `automail`, `jet_boots`) arrive with their art (Task 10); code must not assume the list.
- **tgui:** styles in SCSS classes, inline styles only for per-item computed values; every Aphelion UI file starts with
  `// THIS IS AN APHELION UI FILE`; theme tokens with fallbacks; no `theme` prop.

## Review Focus

1. **Two characters, same finish, different colours, or one with `allow_emissives` off:** each body draws its own colours
   and glow; the shared `limb_icon_cache` must never serve one to the other (key includes colours, glow and alpha). Test in
   Task 3.
2. **Switching a slot from a recolourable finish to a brand finish or none, in the preview:** the limb loses the paint, the
   glow and the Muscular fit; clothes refit at the spawned limb's size. Test in Task 3 (`augment_paint_fit`).
3. **A hand-edited or imported save with a bad colour string, an unknown slot or a slot whose finish is not recolourable:**
   dropped on load, never drawn, never crashes. Test in Task 4 (`augment_paint_save`).
4. **A character with a mutant colour (no skin tones), and a translucent species:** the skin base comes from the humanoid sheet
   and the paint keeps the limb's alpha. Covered by the in-game check (Task 9).
5. **The editor's Readout palette icon while no picker is open:** never a dead or vanishing button; it only acts while its
   slot is the open one. Test in Task 7.

- [ ] **Step 2: The finish datum, matrices and sanitiser** (`finishes.dm`)

```dm
/**
 * A finish drawn on the Muscular outline in four player colours (paint, accent, frame, lights), its lights glowing.
 *
 * Its limbs draw three sheets: their own greyscale image, the skin base, from BULKY_AUGMENTS_SHEET (or its humanoid twin under
 * a mutant colour), and over it copies of that image drawing the finish's packed _paint and _glow states through colour
 * matrices (draw_augment_paint()), so no icon is ever made for a colour. limb_id_override is the finish's id: the prefix of
 * its states in all three sheets.
 */
/datum/robotic_style/recolorable
	abstract_type = /datum/robotic_style/recolorable
	icon = BULKY_AUGMENTS_SHEET
	supported_slots = ARMS|LEGS
	has_digi = TRUE
	bodyshape_override = BODYSHAPE_HUMANOID
	/// The channels its art uses, in channel order, "paint", "accent", "frame" or "lights" -> the label the editor shows.
	var/list/channels
	/// Its colours before a player picks any, "#rrggbb" four times: paint, accent, frame, lights.
	var/default_colors
	/// Colour sets offered in the editor, name -> a colour string as default_colors.
	var/list/presets

/**
 * Returns a recolourable finish's colour matrix for one of its packed states: numeric and 4x4, rows red, green, blue, alpha,
 * as Nova's naga tail builds its (constrict.dm). Never rows of colour strings, which map_colors_inferred() can't flatten for
 * the drawn character preview. Each is built once and kept, by colours, state and alpha.
 *
 * Arguments:
 * - colors: The colour string, paint, accent, frame, lights.
 * - glow: FALSE for the _paint state (paint, accent, frame), TRUE for the _glow state (lights and the two shines).
 * - alpha: The limb's alpha, which the matrix carries.
 */
/proc/augment_paint_matrix(colors, glow, alpha = 255)
	var/static/list/matrices = list()
	var/key = "[colors][glow ? "g" : "p"][alpha]"
	. = matrices[key]
	if(.)
		return
	var/list/rows = glow \
		? list(copytext(colors, 22, 29), AUGMENT_SHINE_W, AUGMENT_SHINE_X) \
		: list(copytext(colors, 1, 8), copytext(colors, 8, 15), copytext(colors, 15, 22))
	var/list/matrix = list()
	for(var/row in rows)
		matrix += rgb2num("[row]00")
	matrix += list(0, 0, 0, alpha)
	for(var/i in 1 to length(matrix))
		matrix[i] /= 255
	matrices[key] = matrix
	return matrix

/**
 * Returns `colors` lowercased when it is four "#rrggbb" colours run together, else null.
 */
/proc/sanitize_augment_colors(colors)
	var/static/regex/valid = regex(@"^(#[0-9a-fA-F]{6}){4}$")
	if(!istext(colors) || !valid.Find(colors))
		return null
	return LOWER_TEXT(colors)

/// The editor's suggested colours for paint, accent and frame.
GLOBAL_LIST_INIT(augment_paint_metal_swatches, list("#e8eaee", "#c4c8d0", "#969ba8", "#5a5e66", "#26262b", "#c9a54a", "#b56b3c", "#b2202a", "#2e5fa8", "#3c7a4a", "#6a3fa0", "#e6e0d0"))
/// The editor's suggested colours for lights.
GLOBAL_LIST_INIT(augment_paint_light_swatches, list("#46ebff", "#5fd4ff", "#3d7bff", "#9b5cff", "#ff3dcf", "#ff2d28", "#ff8a3d", "#ffcc33", "#b4ff3d", "#3dffb0", "#f4f8ff"))
```

```dm
/obj/item/bodypart
	/// A recolourable finish's colours, "#rrggbb" four times: paint, accent, frame, lights. Null on every other limb, so only
	/// a limb wearing one draws its paint and glow (draw_augment_paint()) or keys its icons by them.

	/// A slot without one draws its finish's default.
	var/list/augment_limb_colors = list()

/**
 * Sets a limb up to draw this finish, whatever augment item it is on: its skin base as its own greyscale image, its paint and
 * glow in `colors`, its lights glowing while `prefs` allows emissives (one made without prefs, like an admin spawn, glows),
 * and its clothes fitted as a Muscular limb's. muscle_size is set here at runtime: a typed one would make
 * init_fitness_limb_families() take the limb type for a fitness family.
 *
 * Arguments:
 * - limb: The limb, already given this style's limb_id and icon.
 * - colors: The slot's colour string, or null for the finish's default.
 * - prefs: The preferences the limb is made from, if any.
 */
/datum/robotic_style/recolorable/proc/apply_to(obj/item/bodypart/limb, colors, datum/preferences/prefs)
	limb.should_draw_greyscale = TRUE
	limb.augment_colors = sanitize_augment_colors(colors) || default_colors
	limb.is_emissive = prefs ? !!prefs.read_preference(/datum/preference/toggle/allow_emissives) : TRUE
	limb.muscle_size = MUSCLE_SIZE_MUSCULAR
	limb.update_augment_skin_sheet()

/**
 * Takes a recolourable finish off a limb, if it had one: its colours, its glow and its Muscular fit go back to its type's own.
 */
/obj/item/bodypart/proc/clear_augment_finish()
	augment_colors = null
	is_emissive = initial(is_emissive)
	muscle_size = initial(muscle_size)

/**
 * Points a recolourable finish's limb at the skin sheet in its owner's skin ramp: the humanoid one under a mutant colour.
 */
/obj/item/bodypart/proc/update_augment_skin_sheet()
	icon_greyscale = species_color ? BULKY_AUGMENTS_SHEET_HUMANOID : BULKY_AUGMENTS_SHEET
```

```dm
/datum/unit_test/augment_paint_cache/proc/put_on_finish(mob/living/carbon/human/body, datum/robotic_style/recolorable/finish, colors)
	var/obj/item/bodypart/arm/right/robot/arm = allocate(/obj/item/bodypart/arm/right/robot)

/**
 * The paint colour `body`'s right arm draws, as "#rrggbb": the red row of its _paint copy's matrix, which BYOND reads back as
 * 20 numbers. Read from the body's own cached images, as a draw serves them.
 */
/datum/unit_test/augment_paint_cache/proc/paint_drawn(mob/living/carbon/human/body)
	var/obj/item/bodypart/arm = body.get_bodypart(BODY_ZONE_R_ARM)
	for(var/image/drawn as anything in body.limb_icon_cache[arm.get_cache_key()])
		if(drawn.icon_state == "[arm.limb_id]_[BODY_ZONE_R_ARM]_paint")
			var/list/matrix = drawn.color
			return rgb(round(matrix[1] * 255), round(matrix[2] * 255), round(matrix[3] * 255))
	TEST_FAIL("The right arm draws no _paint copy.")
```

- [ ] **Step 1: State and colour helpers** (top of `paint.tsx`)

```ts
const CHANNELS: PaintChannel[] = ['paint', 'accent', 'frame', 'lights'];
const DIRS = ['south', 'east', 'north', 'west'] as const;
const SHINE_W = '#fafbff';
const SHINE_X = '#c4c7d0';

/** The colour string's channel colours, in channel order. */
const split = (colors: string) => CHANNELS.map((_, i) => colors.slice(i * 7, i * 7 + 7));
const join = (parts: string[]) => parts.join('');
const rgb = (hex: string) => [1, 3, 5].map((i) => parseInt(hex.slice(i, i + 2), 16) / 255);

/**
 * An feColorMatrix that sums the input's red, green and blue channels into three colours, as the game's 4x4 matrices do.
 * SVG matrices are output-major: each row is one output channel.
 */
function packedMatrix(r: string, g: string, b: string) {
  const [R, G, B] = [rgb(r), rgb(g), rgb(b)];
  return [0, 1, 2]
    .map((out) => `${R[out]} ${G[out]} ${B[out]} 0 0`)
    .concat('0 0 0 1 0')
    .join(' ');
}

/** Multiplies by one colour, as a greyscale limb's skin base is tinted. */
function tintMatrix(color: string) {
  const [r, g, b] = rgb(color);
  return `${r} 0 0 0 0 0 ${g} 0 0 0 0 0 ${b} 0 0 0 0 0 1 0`;
}

/** Keeps a _glow strip's light (its red channel) as alpha, in the light's colour: the glow's halo in the dark view. */
function lightOnlyMatrix(color: string) {
  const [r, g, b] = rgb(color);
  return `0 0 0 0 ${r} 0 0 0 0 ${g} 0 0 0 0 ${b} 1 0 0 0 0`;
}
```

  Every `<filter>` sets `colorInterpolationFilters="sRGB"` (the default, linearRGB, would not match the game).

```dm
		var/has_paint = FALSE
```
